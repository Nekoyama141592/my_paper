# デジタル庁スタイルのプレゼンテーション設計

## Overview

### 目的と適用範囲

デジタル庁デザインシステムを参考に、明快で読みやすく、落ち着いた日本語のスライドを制作する。デジタル庁のデザインを紹介する発表に加え、研究発表・企画提案・活動報告にも同じ視覚ルールを適用できる。発表テーマや枚数は固定しない。

公式資料が重視する情報の探しやすさやアクセシビリティを、スライドの情報階層と読みやすさに応用する。[デジタル庁「デザインシステム」](https://www.digital.go.jp/policies/servicedesign/designsystem)

白い背景に濃い文字を置き、青は注目させたい要点に絞る。見出し、図表、補足の順に自然に読める構成とし、余白で情報のまとまりを伝える。

### 出典と独自設定の区別

本書は**非公式のプレゼンテーション用スタイルガイド**であり、デジタル庁の公式スライドテンプレートではない。

| 区分 | 本書での扱い |
| --- | --- |
| DESIGN.mdの記述方式 | YAMLの具体値とMarkdownの適用理由を併記する。セクション順は参照仕様に沿う |
| 公式資料から参照する考え方 | 情報の階層、色の役割、可読性、余白の規則性 |
| 公式資料から採用する書体 | Noto Sans JP、コード用のNoto Sans Mono |
| 本書が独自に定義する値 | 使用する色の組み合わせと役割、スライド寸法、文字サイズ、配置、部品、情報量 |

YAMLの色値は本書で選定したパレットであり、公式のプリミティブトークン名やブランド指定色との一致を保証するものではない。公式UIの再現が必要な場合は、その時点の公式デザインデータを別途確認する。

形式の参照：[google-labs-code/design.md](https://github.com/google-labs-code/design.md)、[詳細仕様](https://github.com/google-labs-code/design.md/blob/main/docs/spec.md)。公式資料の確認日：2026年11月18日。専用サイトの表示版：β版 v2.18.2。[専用サイト](https://design.digital.go.jp/dads/)

### 制作時の優先順位

発表ごとの明示指示、内容の正確さと可読性、本書の順に判断する。本書を指定した制作では、別の汎用テンプレートの配色・書体を混ぜない。未指定の部品は既存トークンで構成し、情報量が多いときはページを分割する。

## Colors

### パレットと使い分け

| トークン | 値 | スライドでの役割 |
| --- | --- | --- |
| `primary` | `#0031D8` | 要点、重要な数値、注目する系列、リンク |
| `background` | `#FFFFFF` | 表紙・章扉を含む全ページの背景 |
| `surface` | `#F5F5F5` | 比較欄、補足パネル、表の見出し補助 |
| `emphasis-surface` | `#EEF3FF` | 結論の背景。1ページ1か所を目安にする |
| `text` | `#1A1A1A` | 見出し、本文、図表のラベル |
| `text-secondary` | `#595959` | 出典、補足、ページ番号 |
| `border` | `#767676` | 識別に必要な境界線、図の接続線 |

基本は白・グレー・青で構成する。青の面積を増やして華やかにするのではなく、重要な箇所を少数に絞って強調する。この色数制限は本書独自の制作ルールである。

### 読みやすさの基準

テキストと背景は4.5:1以上、識別に必要な線や図形は隣接背景に対し3:1以上を確保する。薄い面同士の差だけで分類を伝えず、見出しやラベルも添える。色の役割とコントラストの考え方は[公式カラーガイド](https://design.digital.go.jp/dads/foundations/color/)を参照する。

- 青文字は白または `emphasis-surface` に置く。写真へ直接重ねない。
- 青い表見出しには白文字を使う。
- リンクには説明的な文字と下線を付ける。単なる強調語に下線を付けない。
- 比較グラフは青とグレーに加えて、直接ラベル・線種・マーカーを使う。
- 成功・エラーなどを紹介するときだけ意味に対応する色を追加し、文字でも状態を示す。追加色はコントラストを再確認する。

公式の色体系は青だけに限定されない。本書の青中心の配色は、その考え方を利用した一つの選択である。[公式カラーパレット](https://design.digital.go.jp/dads/foundations/color/color-palette/)

## Typography

Noto Sans JPを日本語・英数字の基本書体とし、通常400・強調700を使う。コードやトークン名にはNoto Sans Monoを使う。これらの書体選定は[公式タイポグラフィ](https://design.digital.go.jp/dads/foundations/typography/)を参照する。下表のサイズは投影用に独自設定したものである。

### サイズと単位

本書のpxは1280 × 720の論理キャンバス上の値。PowerPointは13⅓ × 7.5インチを基準とし、座標は `px ÷ 96 = inch`、文字は `px × 0.75 = pt` で変換する。1920 × 1080に画像出力するときは全体を1.5倍し、文字だけを拡大しない。

| 用途 | トークン | 論理px | PowerPoint pt | 行高 |
| --- | --- | ---: | ---: | ---: |
| 表紙・章扉 | `display` | 64 | 48 | 1.25 |
| 各ページの見出し | `heading` | 48 | 36 | 1.3 |
| 小見出し・結論 | `subheading` | 32 | 24 | 1.4 |
| 本文 | `body` | 32 | 24 | 1.5 |
| 図表ラベル・補足 | `caption` | 24 | 18 | 1.5 |
| 出典・ページ番号 | `source` | 20 | 15 | 1.4 |

### 日本語の組版

- 原則左揃え。見出しは1〜2行、本文の箇条書きは3項目程度に絞る。
- 1行は全角18〜28文字を目安とし、助詞や意味のまとまりに配慮して改行する。
- 行頭の閉じ括弧・句読点を避ける。文字の横幅を圧縮して収めない。
- 本文を小さくする前に、文を短くする、図へ置き換える、スライドを分ける。
- 太字は見出しと重要語に限定し、本文全体を太字にしない。
- Noto Sans JPが使えない場合は游ゴシックまたはヒラギノ角ゴシックへ統一して置換し、改行と欠けを再確認する。日本語を含むコードは日本語書体へフォールバックさせる。
- スライドの文字は編集可能なテキストで作る。画像生成で日本語本文を描画しない。

## Layout

### キャンバスと共通配置

以下は本書独自のスライド寸法である。余白を情報の関係性に合わせて統一する考え方は[公式余白ガイド](https://design.digital.go.jp/dads/foundations/spacing/)を参照する。

| 項目 | 値・ルール |
| --- | --- |
| 比率 | 16:9、1280 × 720論理px |
| 左右の余白 | 64px、有効幅1152px |
| 見出し領域 | x=64、y=48、w=1152、h=128以内 |
| 本文・図解領域 | x=64、y=200、w=1152、h=416以内 |
| フッター | y=648〜676。本文領域から32px以上離す |
| 2列 | 各560px、列間32px |
| 3列 | 各368px、列間24px |
| パネル内部 | 32px。図表の密度に応じて24pxまで調整可 |
| 要素間隔 | 8 / 16 / 24 / 32 / 48 / 64px |

見出しが1行のページも本文の開始位置を揃える。表紙と章扉は共通配置の例外とし、同じ左右余白を維持する。すべての要素をグリッドに載せる必要はないが、主要な左端と上端は揃える。

### 情報量と読み順

1枚につき中心となる主張を1つ置く。読み順は見出し、図表または本文、補足、出典とする。視線を何度も左右に往復させない。カードは並列項目に使い、文章をすべてカード化しない。

ページ番号は右下だけに配置し、右上には置かない。出典は左下に短い資料名・発行主体を置き、詳細URLはリンクまたは発表者ノートに記載する。長い出典一覧は独立した参考資料ページにする。

## Elevation & Depth

投影資料では影を使わず、余白・背景色・線でまとまりを示す。浮遊するカード、半透明のガラス表現、立体的な文字、背景のグラデーションは使わない。これは本書独自のスライド用ルールであり、公式UIのエレベーション仕様を置き換えるものではない。

## Shapes

表、結論帯、画像枠は角丸なし。説明パネルは半径8pxで統一する。図解の線は2px以上、矢印は3pxを目安にする。形状の違いを分類に使う場合は、ラベルにも同じ区別を記す。

角の形状を部品ごとに決める考え方は[公式の角の形状](https://design.digital.go.jp/dads/foundations/corner-shapes/)を参照する。ここでの半径や線幅は本書の設定である。

## Motion & Micro-interaction

アニメーションなしを標準とする。手順の説明で段階表示を使う場合は順番に出現させるだけにし、移動・回転・点滅を使わない。PDFでも内容が欠けない完成状態を用意する。スライド上の説明用ボタンを実際に操作できるものとして案内しない。

## Voice & Content Strategy

### 書き方

簡潔・具体的・穏やかな日本語を使う。専門語は初出で説明し、見出しにはそのページで伝えたい内容を書く。「概要」だけでなく「色と文字の役割を揃える」のように具体化する。

- 良い例：見出しを揃えると、必要な情報を探しやすくなる。
- 避ける例：圧倒的に革新的なデザインで、すべての課題を解決する。

公式資料の説明、自分の解釈、制作上の提案を区別する。検証していない改善効果や数値は断定しない。架空の画面やデータは「説明用の例」と明記する。

### デジタル庁のデザインを紹介する場合の構成例

以下は内容構成の提案であり、公式の推奨章立てではない。他のテーマにこのスタイルを使う場合は置き換える。

| ページ | 伝える内容 | レイアウト |
| --- | --- | --- |
| 1 | デジタル庁のデザインから学ぶ、伝わる情報設計 | 表紙 |
| 2 | 利用する人の読みやすさ・探しやすさを考える | 主張＋具体例 |
| 3 | デザインシステムを構成するルール・部品・ガイド | 3列の整理 |
| 4 | 色に役割を与えて、重要な情報を見つけやすくする | 色見本＋説明 |
| 5 | 文字と余白で情報の階層をつくる | 同じ内容の比較 |
| 6 | 部品を組み合わせて一貫した画面をつくる | 画面例＋注釈 |
| 7 | 色だけに頼らず、文字や形でも伝える | 比較＋ラベル |
| 8 | プレゼンテーションへ応用する3つのルール | 要点3つ |
| 9 | 参照資料 | 出典一覧 |

「ルール・部品・ガイド」は発表用の要約表現。公式サイトではデザイン言語、UIコンポーネント、ガイドライン等から構成されることが説明されている。[公式の構成説明](https://design.digital.go.jp/dads/)

## Components

### 表紙・章扉

表紙は白地に黒い大見出しを左揃えで置く。タイトルは2行まで、下に短い副題、その下に発表者・日付を置く。青の線または小さなカテゴリラベルを1つ添える。章扉は章番号、章題、1行の説明で構成し、大きな空白を残す。

### 主張＋図解

上部に主張、本文領域に図解を1つ置く。プロセス図は3〜4段階までを標準とし、順番と因果関係を区別する。因果を裏付ける根拠がない場合は因果関係として描かない。下部に結論帯を使う場合、図解領域の高さを縮めて重なりを防ぐ。

### 比較

2列で同じ項目を同じ順番に並べる。説明する差以外の文字量・サイズ・尺度をできるだけ揃える。「例A／例B」「変更前／変更後」などのラベルを付ける。改善案を青で示す場合も、色だけで優劣を伝えない。

### パネル

2列または3列に限定し、見出しと短い説明を入れる。3列の説明は全角10文字程度×3行以内を目安にする。説明が長い場合は2列か縦の箇条書きへ変更する。アイコンは意味の理解に必要なときだけ添える。

### 表・グラフ

表は見出し行を含め6行・4列以内を目安にする。数値は右揃え、項目名は左揃え。単位、対象期間、母数、出典を必要に応じて示す。罫線は必要な区切りだけにする。図表ラベルは原則24px以上。

グラフは青で注目する系列、グレーで比較対象を示し、直接ラベルを付ける。棒グラフの値軸は原則ゼロ始まり。3D化、装飾的な遠近法、意味のない二重軸を避ける。元データがない数値を補わない。

### 画面例・アイコン

画面例は説明する箇所が読める範囲に切り出し、全画面を小さく貼り付けない。注釈は番号と説明を対応させ、1枚につき3か所までを目安にする。編集や再構成を行った場合はその旨を明記する。

アイコンは単一の線画体系で揃え、原則として文字ラベルを併記する。公式素材を用いる場合は配布元と利用条件を確認する。公式ロゴを独自に再描画したり、発表者の所属・制作主体を誤認させる形で置いたりしない。

## Do's and Don'ts

### 制作・確認チェックリスト

- [ ] 1枚で伝える主張が見出しから分かる。
- [ ] 表紙・章扉を含め白背景で統一され、強調色の役割が一定である。
- [ ] 本文32px、図表ラベル24pxを基本とし、情報量のために縮小していない。
- [ ] 文字・意味のある図形と背景のコントラストを確認した。
- [ ] 色だけで分類・状態・結論を示していない。
- [ ] 文字切れ、要素の重なり、禁則違反、フォント置換による改行崩れがない。
- [ ] 出典とページ番号が本文に重ならず、番号は右下にある。
- [ ] 画像には説明または代替テキストがあり、編集可能な資料では読み上げ順も確認した。
- [ ] 引用・事実・独自の提案が区別され、架空のデータが紛れていない。
- [ ] 公式ルールと本書独自の値を混同していない。
- [ ] 実際にスライドを作成した際は、全ページを画像またはPDFへ書き出し、一覧と各ページで確認した。
